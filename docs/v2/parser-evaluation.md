# V2 parser evaluation — plan and decision rule (WP4)

**Pre-registered 2026-11-26, before any candidate was run on the validation set.**
Changing the metrics or the rule after a run needs an owner decision recorded here, with the reason.

## Question
Which PDF reader feeds the engine's document model (`engine/app/schemas/document.py`), and therefore which engine host it needs?

## Candidates
| Candidate | License | Runs where | Status |
|---|---|---|---|
| Current TypeScript reader (pdf.js + `layout-tables.ts`) | Apache-2.0 (pdf.js) | web | Baseline. Needs an export of its pages and tables as the document model (`web/scripts/export-document-model.ts`, WP4 task). |
| pdfplumber | MIT | engine | Adapter in `engine/app/parsing/pdfplumber_reader.py` |
| PyMuPDF | **AGPL-3.0** | engine | Adapter in `engine/app/parsing/pymupdf_reader.py`; evaluation-only dependency group. Shipping it needs an owner decision on AGPL. |
| Docling | MIT (models: own licenses) | engine container with ML models | Adapter not written yet: it needs its layout models downloaded, which this workspace can't do. Next on the owner's machine or in CI. |
| Nemotron Parse | provider terms | hosted | Paid call; runs only after the free candidates, on validation only. |
| LlamaParse / Reducto / Azure DI | commercial | hosted | Ceiling reference only, if the owner approves the spend. |

No candidate calls a language model except the hosted ones.

## Data
1. **Synthetic dev fixtures** (in git, generated by `engine/evaluation/synthetic.py`): benefit tables with level columns, two-row headers, wrapped cells, footnotes, an SBC-style question/answer table, a printed page number that differs from the PDF page. Used to build and debug adapters. **Never used for the decision.**
2. **Validation set** (`evaluation/manifests/corpus-v2.json`, split `validation`): the decision is made here, on the answer keys written in WP2.
3. Blind batches are never used for parser choice.

## Metrics (per document type, raw counts)
1. **Table binding** (primary): for every key value that sits in a table, the reader produced a cell with that text whose row label matches the key's benefit label and whose column header path contains the key's level or network tier. Score = bound / keyed values.
2. **Text recall:** key values outside tables found in page text (paragraphs, footnotes, exclusions, conditional clauses).
3. **Reading order:** for keyed passages that span lines, the lines come out in the order the document reads.
4. **Page labels:** printed page detected where the page carries one.
5. **Speed:** p50 and p95 seconds per page on the same machine.
6. **Footprint:** installed size and container image size.
7. **License:** permissive / copyleft / commercial.

## Decision rule
1. Exclude any candidate with a copyleft or commercial license unless the owner has approved that license.
2. Among the rest, pick the highest **table binding** on validation (all types pooled; ties broken by the lowest per-type minimum).
3. It must also be within **2×** the fastest candidate's p95 seconds per page, and no worse than the baseline on text recall.
4. If the top two are within 2 points on table binding, pick the smaller footprint.
5. If no candidate beats the baseline on table binding, keep the baseline reader and record that the engine reads the web app's export.

The chosen reader sets the engine host: a small container (pdfplumber or PyMuPDF) or a container with ML models (Docling). The host choice and its Terraform follow in WP12.
